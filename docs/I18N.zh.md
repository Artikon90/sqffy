# 本地化（i18n）

[English](./I18N.md) · [Русский](./I18N.ru.md) · **中文**

SQffy 的界面字符串都经过 `src/i18n.rs`。不要在 `app`、`picker`、`meta`、`render`、`provision` 或 `mcp` 里写死面向用户的文字。把键加到 locale 文件里。

## 文件

| 路径 | 作用 |
| --- | --- |
| `locales/en.toml` | 默认语言，也是某个键缺失时的回退 |
| `locales/ru.toml` | 俄语 |
| `locales/zh.toml` | 中文（简体） |
| `src/i18n.rs` | 加载器、`t` / `tr`、语言检测 |

目录在**编译期嵌入**（`include_str!`）。改 toml 要到下一次构建才生效，不是运行时热加载。嵌套的 TOML 表会被压成点分键（`picker.title`、`meta.help`）。

## API

```rust
i18n::init(cli.lang.as_deref()); // 启动时一次
i18n::t("picker.title");
i18n::tr("picker.connecting", &[("name", &name), ("driver", "sqlite")]);
```

locale 字符串里的占位符写成 `{name}`。缺键时返回键本身，所以缺口会在屏幕上显示成 `picker.title`，而不是空行。

## 语言解析

先匹配到的获胜：

1. `--lang`（`en`、`ru`、`zh`）
2. `SQFFY_LANG`
3. `LC_ALL`，然后 `LC_MESSAGES`，然后 `LANG`
4. `en`

`C` 和 `POSIX` 会被跳过。未知值回退到英语。

`normalize_lang` 只留主子标签。`ru-RU` 和 `ru_RU` 是 `ru`。`zh`、`zh-CN`、`zh-TW`、`zhcn`、`zhtw` 和 `cn` 都是 `zh`（一份目录，`locales/zh.toml`）。

## 增加一种语言

1. 把 `locales/en.toml` 复制为 `locales/<code>.toml` 并翻译。键集合保持一致。
2. 在 `i18n::load_embedded` 里加一个分支，在 `normalize_lang` 里加一个 `match` 臂。
3. 在三份 README 的语言行（`--lang`）里写上这个代码。
4. `cargo test`。代码用到的键应该能解析；英语目录仍然是回退。

## 增加一条字符串

1. 在 `en.toml`、`ru.toml` 和 `zh.toml` 的同一嵌套位置加上这个键。
2. 在代码里调用 `t("…")` 或 `tr("…", …)`。
3. 键要短、要稳定：`area.thing`（`picker.ask_name`）。

不要用 `format!` 去包一句已经翻译好的话。占位符放在目录里，这样每种语言可以有自己的词序。
