# Localization (i18n)

SQffy UI strings go through `src/i18n.rs`. Never hardcode user-facing text in
`app` / `picker` / `meta` / `render` — add a key to the locale files instead.

## Files

| Path | Role |
| --- | --- |
| `locales/en.toml` | Default / fallback |
| `locales/ru.toml` | Russian |
| `locales/zh.toml` | Chinese (简体) |
| `src/i18n.rs` | Loader, `t` / `tr`, language detect |

Catalogs are **embedded at compile time** (`include_str!`). Nested TOML tables
are flattened to dotted keys (`picker.title`, `meta.help`).

## API

```rust
i18n::init(cli.lang.as_deref()); // once at startup
i18n::t("picker.title");
i18n::tr("picker.connecting", &[("name", &name), ("driver", "sqlite")]);
```

Placeholders use `{name}` syntax inside locale strings.

## Language resolution

1. `--lang ru` / `--lang en` / `--lang zh`
2. `SQFFY_LANG`
3. `LC_ALL` / `LC_MESSAGES` / `LANG`
4. fallback `en`

Unknown languages fall back to English (with English catalog as secondary
fallback if a key is missing in the active locale).

## Adding a language

1. Copy `locales/en.toml` → `locales/<code>.toml` and translate.
2. Add a branch in `i18n::load_embedded` and `normalize_lang`.
3. `cargo test` — keys used in code should resolve.

## Adding a string

1. Add the key to `en.toml`, `ru.toml`, and `zh.toml` (keep parity).
2. Call `t("…")` or `tr("…", …)` from code.
3. Prefer short stable keys: `area.thing` (`picker.ask_name`).
